Readiness scoring methodology

How NUMPA turns raw checks into a single, explainable readiness score — and why that score should never be treated as a guarantee.

How the score is calculated

Each applicable dimension gets a normalized quality value between 0 and 1, weighted by its configured importance, then combined into a single 0–100 score:

score = 100 × ( Σ wi · qi ) / ( Σ wi )   for i in applicable dimensions

Only dimensions that were successfully evaluated contribute to the score. A dimension NUMPA couldn't evaluate is excluded — it does not default to a neutral 0.5, since that would silently hide missing information.

Default scoring dimensions

DimensionDefault weightWhat it measures
Completeness20%Missing values and missing required information
Validity & consistency15%Invalid values, type mismatches, format issues
Record integrity10%Duplicate and structurally broken records
Feature suitability15%Relevance and usability of input features
Target suitability15%Target availability, validity, task compatibility
Data sufficiency10%Whether available data is adequate for the task
Leakage & validation15%Leakage risk and validation strategy fit

These weights are configurable per assessment. In the Custom Model Studio, you can define your own weighting for a specific task or company standard.

Finding categories

Every check NUMPA runs resolves to one of four states, so you always know the difference between a real problem and a limitation of the assessment itself:

StatusMeaning
Confirmed issueA problem supported directly by the data or configuration
Suspected issueEvidence suggests a risk that needs human review
UnknownNot enough information was available to evaluate the check
Not applicableThe check doesn't apply to this task or dataset

What this score is not

  • It does not guarantee predictive accuracy of any model trained on the dataset.
  • It does not automatically make a dataset ML-ready — cleaning decisions remain yours.
  • It does not replace domain expertise, especially for semantic leakage that no automated check can see.

Critical risks — like confirmed target leakage — always stay visible in the results, even when the overall score looks high. A high aggregate score is never allowed to bury a specific, serious problem.
